Qu’est-ce que Pharo-LLM ?

Au début, mon objectif était assez simple : je voulais avoir les outils nécessaires pour intégrer les LLM dans Pharo. Mais je ne voulais pas Pharo-LLM d’être juste un autre wrapper autour d’une API externe. L’idée est progressivement devenue de construire un ensemble d’outils et de bibliothèques qui nous permettent de créer, d’exécuter et d’interagir avec les LLM directement à l’intérieur de Pharo. Plus important encore, je veux que ces outils se sentent natif de Pharo. Cela signifie intégrer les LLM avec les éléments qui rendent Pharo intéressant : les objets, les inspecteurs, les débogueurs et nos flux de travail de développement.

Aujourd’hui, l’écosystème Pharo-LLM comprend plusieurs projets :

  • ChatPharo — une interface conversationnelle à l’intérieur de Pharo.
  • Pharo-Copilot — un moteur de complétion de code intelligent.
  • Pharo-Infer — un moteur d’inférence pour les LLM dans Pharo. Et les expériences et outils plus qui sont encore en cours de développement.

L’objectif n’est pas simplement de connecter Pharo aux LLM. L’objectif est d’explorer ce qu’un Écosystème LLM conçu spécifiquement pour Pharo pourrait ressembler.

De l’utilisation des LLM à leur contrôle

En développant Pharo-LLM, j’ai commencé à penser à un autre problème. Aujourd’hui, lorsque nous utilisons un LLM, nous dépendons souvent d’un fournisseur externe. Nous dépendons (de leur API ; de leurs prix ; de leurs limites de taux ; de leur infrastructure ; et d’une connexion réseau) Lorsque nous travaillons avec du code source ou des projets privés, nous devons également penser à la confidentialité.

Donc, ma question initiale est Comment pouvons-nous appliquer les LLM dans Pharo ? et est lentement devenu une autre question : Comment pouvons-nous construire un écosystème LLM souverain dans Pharo ?. Pour moi, il y a trois parties importantes à cela, i. Avoir les outils à l’intérieur de Pharo pour créer, exécuter et interagir avec les LLM, ii. Avoir la capacité de former et d’affiner nos propres modèles, iii. Avoir la capacité de déployer et de maintenir nos propres modèles. C’est la direction que je veux maintenant explorer avec Pharo-LLM.

Modèles de formation pour Pharo

Un exemple concret est Pharo-Copilot. Pharo-Copilot est un moteur de complétion de code qui utilise des LLM pour prédire les prochains jetons de code Pharo. Au lieu de remplir un seul jeton ou un seul mot, l’idée est de générer complétions de code multi-jetons. Mais si nous voulons un modèle vraiment utile pour Pharo, nous en avons besoin pour comprendre Pharo. Nous avons donc expérimenté avec les LLM de code poids ouvert. Vous pouvez trouver l’article décrivant ce travail et nos résultats ici.

Exécuter nos propres modèles

Former ou peaufiner un modèle n’est qu’une partie du problème. Après cela, nous devons l’exécuter. Aujourd’hui, Pharo-LLM peut interagir avec des API cloud telles que ChatGPT, Claude et DeepSeek. Nous pouvons également utiliser des API locales fournies par des outils tels que Ollama, LM Studio ou vLLM. Mais je voulais explorer ce qui se passerait si nous allions plus loin. Et si nous pouvions exécuter le modèle à travers une infrastructure qui appartient directement à l’écosystème Pharo ? C’est pourquoi j’ai commencé Pharo-Infer. Un moteur d’inférence charge un modèle de langage formé et le prépare à l’exécution. Il convertit les invites en jetons, génère des jetons en sortie et gère des éléments tels que la mémoire, le contexte, l’échantillonnage et la diffusion en continu pendant la génération. Avec Pharo-Infer, l’idée est de fournir cette couche d’inférence dans le cadre de l’écosystème Pharo, en utilisant des composants open-source tels que llama.cpp pour l’exécution de modèles de bas niveau.

Ce dernier point est particulièrement important pour moi. Pharo est un environnement où nous aimons l’idée que tout est moulable. Si notre infrastructure d’IA vit complètement en dehors de Pharo, derrière une autre application ou un autre service, alors nous perdons une partie de cette idée.

Bien sûr, avoir notre propre moteur d’inférence a aussi un coût. Cela signifie plus de travail de maintenance, d’optimisation des performances, de gestion du matériel et de gestion des modèles. Mais en retour, cela nous donne une plus grande indépendance, une meilleure confidentialité et la possibilité d’une intégration beaucoup plus profonde avec Pharo.
